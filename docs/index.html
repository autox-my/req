req

A git-native requirements engine that tells you when a requirement’s meaning changed, and in which direction.

  • req, in one page: the problem and a real before-and-after, for people who decide, plan or explain.
  • req’s architecture: twelve parts, from authoring to a signed Baseline, each labelled with whether the code still satisfies the requirements it was recorded against; every one of its 27 parts is on the detailed page.
  • How it works: diagrams, for engineers.
  • Adopting req: install it and run the loop on your own corpus.
  • README and the repository (Apache-2.0).

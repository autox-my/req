# M1-2 — say what the address is, and bound the bet to what was measured

Task id: `M1-2`. Docs only; runs in parallel with M1-1 (`docs/specs/M1-1-identity-coverage.md`)
and shares two files with it, each unit owning a different section: `README.md` (M1-2 the bet
section, M1-1 the status line) and `docs/canonical-hashing.md` (M1-2 the §1 sentence, M1-1 the new
Tier-1 rule). Docs merge first; M1-1 rebases.
Code baseline: `b56bca3`.

## Why

An architecture review on 2026-11-02 found two false merges in the dogfood corpus (REQ-0020 and
REQ-0004; M1-1 fixes them) and two framing problems this unit fixes in prose:

1. **The bet is stated more broadly than it was measured.** `AGENTS.md` bounds it ("zero false
   merges on the parity + adversarial-trap corpora"), but `README.md` does not ("no rewording,
   however loose, collapses two different requirements into one", and "Zero false merges on all
   of them"). The external corpora's equivalent pairs are generated by the same transforms Tier-1
   implements, and their mutations are three (shall→may, shall→shall not, first-verb swap), so
   the measurement covers only what the rules were built to handle.
2. **"Identity" is the wrong word for the address.** Relations, tests, Decisions and people refer
   to `claim_id`, which is the stable identity; a requirement whose bound tightens is still the
   same requirement with a new meaning. The address is a **meaning fingerprint**: the comparison
   primitive for drift against a signed Baseline and for duplicate hints.

## What to write

1. **`docs/adr/0020-the-address-is-a-meaning-fingerprint.md`**, `status: proposed` (the owner
   ratifies; never write `accepted`). It supersedes only the *identity wording* of ADR 0001; the
   unit-is-a-claim decision stands. Follow the 0008 → 0009 precedent: add a status line to ADR
   0001 pointing at 0020, and change nothing else in 0001's text. The ADR records:
   - the decision: `claim_id` is identity; the address is a derived meaning fingerprint;
   - the consequence it **enables but does not perform**: a later claim format that stops storing
     `canonical.form` and `address` in claim files and computes them at load, storing
     fingerprints only in Baseline manifests (so a `RULES_V` bump rewrites no claim file);
   - the loss that move names rather than hides: "a hand-edited digest is a critical finding"
     disappears with the stored digest, and per-claim drift against a signed manifest replaces it;
   - the rejected alternative: keeping the address as identity (with the reason above).
   It must not claim the bet is validated or invalidated; cite M1-1 for the false merges.
2. **`README.md`, the "bet" section only.** State the bet as bounded to the corpora that measured
   it, say in one sentence that the equivalence side of the external corpora is generated by the
   Tier-1 transforms (so a 0% false-split rate there is expected, not evidence of paraphrase
   collapse), and that independent paraphrase measurement is open. Do not touch the "Status"
   section's `RULES_V` line; M1-1 owns it.
3. **`CONTEXT.md`**: add *meaning fingerprint* as a term (glossary only, no implementation
   detail), and adjust the existing address/identity entry to point at it.
4. **`docs/design.md` §1 and `docs/canonical-hashing.md` §1**: one sentence each where they call
   the address identity, pointing at ADR 0020. Nothing else in those files.
